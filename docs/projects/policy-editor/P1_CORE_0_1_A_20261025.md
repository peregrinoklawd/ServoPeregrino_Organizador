## Objetivo e limites

Entregar núcleo Policy em **addon source opcional**, dependência de Nexus, com validação de `PolicyExport`, preparação de índices case-insensitive, contextos e avaliações puras. Sem carregar `CfgSPORGPolicy`, sem ler `server.cfg`, sem persistência, interface, integração Items/Weapons, atualização de cache, sincronismo/autoridade MP, PBO ou `CfgRemoteExec` global. Os loaders são P2; o editor P5; executor autoritativo MP P6.

Esta fase não faz `isClass` para inferir existência de equipamento e **não faz** `compatibleItems`/`compatibleMagazines` para decidir compatibilidade física; Policy responde somente autorização por classname. Os classnames de Weapons com prefixo numérico são aceitos pelo mesmo contrato P0.

## Contrato de execução P1

Entrada validação `[_hashMapPolicyExport] call ..._fnc_validateExport` → Nexus Result com `data.export`, `data.whiteIndex`, `data.blackIndex`, `data.conflicts`. HashMaps privados no contexto não são política autoritativa.

Criar contexto `[_hashMapPolicyExport, "ACTIVE", "NONE"] call ..._fnc_createContext` → `data.context` contendo `snapshot` + índices. Em ACTIVE malformado, retorna `success=false`, `code=POLICY_INVALID`, mas entrega `data.context` com `state=INVALID` para o consumidor falhar fechado.

Consulta `[_context, "ItemGPS", false] call ..._fnc_evaluate` → Nexus Result com `data.decision` do schema `SPORG_POLICY_DECISION`. **`success=true` indica que foi produzida uma decisão, não que foi permitido**: sempre usar `data.decision.allowed`. No P1, `revision=0` e `fingerprint=P1_NON_AUTHORITATIVE`; não confundir `source` com credencial. O servidor deve validar toda aplicação em P6, e P2 definirá snapshot efetivo.

Consultar `[_context] call ..._fnc_snapshot` → cópia do DTO. Nunca presumir permissão pela ausência de mod; `ABSENT` retorna `POLICY_ALLOW_OPEN` apenas com `required=false`.
